ntn-slice: network slicing on a LEO satellite cell in ns-3

ns-3 module that enforces per-slot RBG quotas per slice in the 5G-LENA MAC on a LEO cell, with pass-aware quota controllers and p99 SLA monitors.

What ntn-slice does

ntn-slice is an ns-3 module for network slicing on a non-terrestrial (LEO satellite) cell, in which a 5G-LENA proportional-fair scheduler enforces a per-slot resource block group quota for each slice and lends unused groups to other slices. It also provides S-NSSAI and slice-profile classes, quota controllers that follow the satellite pass, and an isolation monitor that reports per-slice delay percentiles.

Accompanying studyQuota, Priority or Rate Cap? Matching the Slicing Mechanism to the Promise on a Receding Low Earth Orbit Satellite. Code and data are in this repository.

What it models

The core of the module is NtnSliceQuotaScheduler, derived from the 5G-LENA OFDMA proportional-fair scheduler. A slice with demand receives at least floor(quota x RBGs) resource block groups per slot, and leftover groups go to any slice with data, so the partition is enforced in the MAC rather than labeled on packets. Quotas are set by controllers in the examples: from the satellite ephemeris, from measured backlog and bytes per RBG, or from a tenant rate contract with a delivered-rate trim (TrimmedQuota). The quota scheduler acts on the downlink only; the uplink stays plain proportional fair.

Around the scheduler sit the slice vocabulary of 3GPP TS 23.501 (S-NSSAI as 8-bit SST plus 24-bit SD, 5QI), default eMBB, URLLC and mMTC profiles after TS 22.261 Table 7.1-1, and a flow selector that matches DSCP, port ranges and application labels. A helper applies a GEO mode-skip rule for latency-bound slices, treating satellites above 30 000 km as GEO. SliceIsolationMonitor keeps a delay histogram, so a reported p99 is a percentile and not a mean, and records breach events. SliceOrchestratorXapp computes a PRB split for an RL policy, but it is a shadow allocator whose decisions are logged and do not reach the MAC. The examples run over SGP4 satellite geometry with TR 38.811 excess loss on a 5G-LENA cell, and the module cites TS 38.300, TS 38.101-5 and TR 38.821 for QoS flow mapping, NTN FR1 bandwidths and latency budgets.

Install

Every module ships in the ready-built container image of the toolkit (version 2.7.1):

docker pull uzairdocker69/ns3-ntn-toolkit:latest
docker run --rm -it uzairdocker69/ns3-ntn-toolkit:latest bash

To build from source, clone ns3-ntn-toolkit, which vendors this module under contrib/, or follow the README of this repository (branch ntn-slice-v2).
